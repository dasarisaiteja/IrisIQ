IRIS PROJECT – FRONTEND DETAILED REQUIREMENTS
Screen-by-screen UI/UX + button behavior + navigation + validation + role-based access
1. Objective
Build the complete IRIS frontend from the public website through authentication, role dashboards, student registration, left/right eye scanning, analysis processing, report display and PDF access. Every screen must be connected to backend APIs; no assessment result may be hard-coded.

11. Left Eye Scan – Exact Flow
Click Start Left Eye Scan.
Request camera permission if required.
Open left-eye scan interface.
User positions eye according to instructions.
Capture/Scan sends image/scan payload to backend.
Show Processing.
On backend success, mark Left Eye Completed.
On failure, show reason-safe error and Retry.
12. Right Eye Scan – Exact Flow
Click Start Right Eye Scan.
Open right-eye scan interface.
Capture/Scan sends right-eye data.
Show Processing.
On success, mark Right Eye Completed.
On failure, show error and Retry.
13. Scan Rules
Left and right scans must use the same Assessment ID.
Frontend cannot manually mark a scan completed.
Continue remains disabled until backend confirms both scans.
Prevent duplicate submission while an upload is processing.
Handle camera denied, invalid scan, timeout and server error states.
Show exactly which eye failed.
14. Analysis Processing
After both scans are completed, enable Generate Analysis/Continue.
Call the analysis/process API.
Show Processing/Analyzing state.
Do not display fake results.
Poll/refresh status or use the API mechanism agreed with backend.
On success open Report; on failure show Retry.

20. Route/Navigation Map
Public Home → Get Started → Student Registration → Success → Eye Scan → Both Eyes Completed → Analysis → Report/PDF
Public Home → Login → Admin Dashboard OR Student Dashboard OR Counsellor Dashboard.
21. Frontend Acceptance Criteria
All three roles work and are protected.
Public website is complete and responsive.
Customer Registration is replaced by Student Registration.
Left and Right Eye are separate mandatory scans.
Both scan completion is backend-confirmed.
Analysis and report are API-driven.
Report contains all approved IRIS sections.
PDF action works through backend.
No hardcoded student/AI/report data.
Desktop/mobile responsive behavior is handled.
